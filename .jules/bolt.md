## 2025-02-19 - Index List Memoization
**Learning:** `get_tickers` reads from the offline DB correctly, but without caching the parsed lists, we re-parse `.get("companies")`, iterate to extract tickers, `.extend()` them, and call `sorted(list(set(tickers)))` every single time it's called. When used repeatedly (e.g. for batch processing across the index), this turns a fast cache lookup into a CPU bottleneck taking over 5.5s for 5000 iterations.
**Action:** Memoize standard parsed lists inside the class instance. This bypasses redundant list processing reducing time to 0.01s. Remember to return a copy or new list to avoid accidental side-effect mutations.
## 2023-10-25 - Vectorized DataFrame Actions
**Learning:** In pandas, looping over a dictionary of corporate actions (dividends/splits) and applying `pd.to_datetime` and `df.index.get_indexer()` inside the loop for each row is severely slow (O(N) operations in Python space). We found a loop processing ~200 actions taking over 0.25 seconds.
**Action:** When updating a DataFrame based on external events, vectorize the date mapping by packing dates into lists, making one `pd.to_datetime` call, getting all indices with a single `get_indexer()` call, and updating the column values via `df.iloc[valid_positions] = valid_amounts`. This changes O(N) python iterations to O(1) vectorized operations yielding roughly a ~100x speedup (0.25s -> 0.002s).
